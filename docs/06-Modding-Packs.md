# NeoSunset modules and packs

Define project-owned versioned formats. Publish schemas, origin requirements, sample fixtures and migration rules before claiming support. Freeze namespaced IDs and pack order in each test case.

| Surface | Contract |
| --- | --- |
| Resource packs | Original models, UI assets, audio, fonts and declared material parameters |
| Data packs | Versioned recipes, terrain parameters, organism definitions and settlement rules |
| Shader packs | Project-defined WGSL entry points with bounded bindings and explicit backend capabilities |
| Modules | Explicit version handshake, capability grants, deterministic hook order and bounded work |

Read archive entries as untrusted data. Reject traversal, duplicate normalized paths and decompressed data beyond the declared limits. Stage and validate dependency graphs, digests and references before atomic activation. Keep the previous pack on failure and report actionable errors. Track pack provenance, format version and ordering with each world.

Prototype a sandbox only once a concrete module needs it. Deny I/O, network, threads and host filesystem by default. Scope allowed operations as capabilities with deadlines, fuel, memory and output limits. Profile the no-listener path. Keep authoritative changes on the server and use matching module graphs for cooperative gameplay. Document versioned event phases, ordering ties and removal policy. Publish at least two independently authored examples before stabilizing the API.
